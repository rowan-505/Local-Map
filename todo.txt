# CoreMap Current-Data Repair Prompts
## General rules for every prompt

Use these rules for all repair tasks:

* Work only on the current production data.
* Do not import new OSM data.
* Do not redesign the import pipeline.
* Do not rebuild search.
* Do not work on addresses.
* Do not clean transport routes unless explicitly requested.
* Use Supabase MCP to inspect the live database.
* Treat the live database as the source of truth.
* Inspect actual table and column names before writing SQL.
* Do not assume old documentation is accurate.
* Never run a large update before producing a dry-run count.
* Never change manually protected rows automatically.
* Never mark imported records as verified automatically.
* Preserve existing IDs and foreign-key relationships.
* Use small transactions.
* Stop after completing the requested step.
* Do not automatically continue to the next prompt.
* Keep implementation simple: SQL scripts, one README, and verification queries.
* Do not create a generic workflow engine or new dashboard pages.
* Do not copy the entire database as a backup.
* Before an update, preserve only the IDs and fields that will actually change.
* All permanent database changes must be represented in a migration or a clearly named repair SQL file in the repository.
* Show the exact SQL and affected-row counts before applying production changes.
* After applying changes, run verification queries and report before/after counts.
